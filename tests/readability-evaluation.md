# 可读性偏好回归协议

维护者选择：1A、2B、3A、4A、5A、6B、7C、8C、9B、10B。十题用于制定规则，不作独立有效性证据。偏好为自然、直接、连贯，解释与结尾需有实际作用，正文与回执分开；不能据此推断全面排斥列表、长句或第一人称。

## 执行

使用 readability-cases.json 中的各组任务，每组在独立会话开始，组内按 turns 顺序发送并保留实际回答。multiturn 第二项包含两个依次发送的修改请求。仅向被测模型提供任务、对应技能及完成任务必要的材料；不提供 criteria、preference_evidence 或预期结果。

比较固定的 v1.2.0 与候选版本，保留完整技能快照及引用文件，使用同一模型、配置、工具权限和非技能上下文。每组每版本至少运行三次，记录模型标识和日期。两版本实际读取资料与工具返回均计入，不能预先向其中一个版本泄露额外案例或评分标准。

## 评分

先判断硬性失败：事实、数量、条件、确定程度或状态失真；未授权改动；删除内容回流；漏掉操作前提；违背用户明确格式。出现这些失败不可用短小或自然补偿。

再匿名随机排序两版本输出，按自然程度、连贯性、解释作用、正文边界分别作偏好比较，允许平局。保留失败原文和理由，不要求逐字匹配参考答案，也不以禁词命中直接判错。维护者复核有争议的结果。发布行为改进结论前，另用未参与设计的同类新场景验证。

## 成本

分别记录普通改写、严格技术文本、代码注释和 lint 场景的实际加载文件、读取次数、工具返回及 token。使用同一 tokenizer 记录编码名称，或使用 API usage；字符数只能标作字符数。区分技能自身占用、完整请求 token 与缓存计费，不把入口减少量称为完整请求节省量。

除文字场景，增加以下加载检查：普通说明不得为完成任务无条件读取所有参考；严格模式读取技术文本；修改 docstring 时读取保护细则并保留 doctest/工具标签；用户要求 lint 时读取用法并运行脚本。检查同一上下文中未变化的资料是否重复加载。

## 结果状态

新增用例默认未执行。结构校验、JSON 解析和 linter 单元测试均不代表行为回归通过。记录每次运行的版本、输入、输出、加载日志、成本、硬性失败和盲评结果，再判断压缩是否值得保留。
